# Unavailability is handled by Availability watches, not by Rules

Whether something becomes a Problem or Alarm because it cannot be reached is configured once, on a separate settings page (Availability watches), instead of inside each Rule; while a watched device is unavailable, Rules about it are Hidden and the Availability watch's Notice takes over. Many devices share the same "Problem after X, Alarm after Y" need, so repeating it per Rule would be tedious, and letting both sources speak would show two Notices for one device (for example "Findus is cleaning" from Home Assistant's last known state next to "Findus is offline"). Rule editors still show the inherited Availability watch under the matching Levels, with a link to change it, so the setting is not invisible from the Rule. Integrations that fail to load are watched by default; devices are opt-in, because watching every unavailable entity would flood the dashboard.
